## Per-comment selection: Copy selected and Clear selected

| Feature id | Behavior | Covering tests |
| --- | --- | --- |
| CMH-PICK-01 | Every side-pane comment card carries an obvious `Select` control in its meta row - a real `<input type="checkbox">` inside its label, so it is keyboard-operable and announced as a checkbox for free, with an `aria-label` naming the comment it picks. Checking it selects that comment THREAD (a picked root carries its replies with it, CMH-THREAD-02/03) and gives the card an accent `cm-card-picked` ring so a selection is legible while scanning the list; unchecking gives it back. Only thread ROOTS are pickable - a reply has no independent pick control. Toggling never re-renders the list, so an inline reply/edit draft open in another card is untouched. | `tests/99-comment-selection.spec.js` - `every comment card carries a Select control that picks that thread (CMH-PICK-01)`; `tests/72-followups.spec.js` - `the side pane search row, dropdown menu items and card edit action are >=44px touch targets on mobile (CMH-RESP-15)` |
| CMH-PICK-02 | While at least one comment is selected, BOTH copy controls (the sidebar `#btnCopyAll` primary and the floating toolbar's `#btnCopyAllTop`) relabel to `Copy selected` and take the matching tooltip, and a selection bar appears under the panel's primary row announcing the live count (`N comments selected`, `aria-live="polite"`). With no selection they read `Copy all` and the bar is hidden, so the all-or-nothing default is unchanged. | `tests/99-comment-selection.spec.js` - `a selection relabels the copy control to Copy selected and counts itself (CMH-PICK-02)` |
| CMH-PICK-03 | `Copy selected` emits ONLY the selected threads - each picked root followed by its replies - in the Markdown body, in the `# ... review (N comments)` heading count, and in the machine trailer's `HANDLED_IDS_JSON` array, so the agent can never mark a comment the reviewer did not hand back as handled and prune it out from under them. Unselected comments appear nowhere in the bundle. | `tests/99-comment-selection.spec.js` - `Copy selected emits only the selected threads, replies included (CMH-PICK-03)` |
| CMH-PICK-04 | A partial hand-back declares itself: the bundle carries a `Scope: selected comments only (N of M open comment threads)` line right after `Source:`, so the agent never reads a missing comment as already handled. A selection is a COMMENT-only scope - the tracked widget-layout, checklist, and editable-note change sections are omitted and their machine-trailer state stays canonical `{}`, because those changes are not selectable and must not ride along on a partial hand-back. With no selection the same document still hands every tracked change back exactly as before. | `tests/99-comment-selection.spec.js` - `a partial hand-back declares its scope and carries no tracked note change (CMH-PICK-04)` |
| CMH-PICK-05 | The selection bar carries a `Clear selection` button that deselects every picked comment and DELETES nothing - the cards, the store, and the copy control all return to the no-selection default. It resets the rendered checkboxes in place rather than re-rendering, so an open inline draft survives. | `tests/99-comment-selection.spec.js` - `Clear selection deselects everything and deletes nothing (CMH-PICK-05)` |
| CMH-PICK-06 | The sidebar `More` menu grows a `Clear selected comments` item that is HIDDEN unless a selection exists. Activating it confirms first through the same `showConfirm` dialog Clear all uses (naming the comments and replies that go with them, cancel-by-default, Escape cancels), then deletes only the selected threads - tombstoning every id, closing any editor or dialog left showing a removed id, dropping the highlights, and saving - leaving every unselected comment intact. Focus returns to the still-visible `More` trigger. | `tests/99-comment-selection.spec.js` - `Clear selected comments shows only with a selection and deletes only those (CMH-PICK-06)` |
| CMH-PICK-07 | The selection is TRANSIENT: it lives only in memory, is never written to `localStorage` and never embedded in an export, so a reload, a shared file, or a second tab starts from the all-or-nothing default. It is also self-pruning - it is resolved against the live thread roots on every read, so a selected comment deleted from its own card, from the in-document dialog, by Clear all, or by a handled-id prune on load simply leaves the selection, and the copy control falls back to `Copy all` once nothing is left picked. | `tests/99-comment-selection.spec.js` - `the selection is transient and prunes a deleted comment (CMH-PICK-07)` |
| CMH-PICK-08 | A comment card ships ONE definition of "an action": `jump`, `edit` and `delete` sit on the SAME row as `Reply` (`.cm-card-acts`) and share its look and feel - the same `cm-card-btn` bordered pill, border, radius, font and padding - instead of the previous split between small plain text buttons on the meta line and an accent pill a row below. `delete` is pushed to the row's end so the destructive action stays clear of `Reply` (CMH-RESP-14), and every one of them keeps the >=44px phone touch target on both axes (CMH-RESP-07/CMH-RESP-15). Opening the inline reply editor stands the WHOLE action group down for the duration, so the composer owns the row. | `tests/99-comment-selection.spec.js` - `jump, edit and delete share the Reply row and its look and feel (CMH-PICK-08)`; `tests/72-followups.spec.js` - `the side pane Reply button and identity Save/Cancel are >=44px touch targets on mobile (CMH-RESP-14)`, `sidebar comment-card action buttons are >=44px tall on mobile (CMH-RESP-07)` |
