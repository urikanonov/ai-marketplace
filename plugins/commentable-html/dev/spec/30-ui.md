| CMH-UI-14 | A chrome control focused while its panel is still SLIDING IN gets its styled tooltip once the control lands, instead of losing it for good. The tip is only ever raised by `focusin`/`mouseover`, so a control that is momentarily outside the visible box during the 0.22s sidebar slide used to be suppressed with no second chance - a keyboard user who opened the panel and immediately tabbed to Search/Sort/More/Help got silence. A suppressed anchor now opens a bounded watch EPISODE (a single `requestAnimationFrame` loop, timed on a monotonic clock): the tip is raised the moment the anchor is inside the visible box, up to `CM_TIP_LAND_MS` (600ms, comfortably longer than the slide) later. Because an anchor counts as visible as soon as it overlaps the box by a pixel - long before a slide settles - the bubble then KEEPS following the control until its box holds still for two frames, so it ends up beside the settled control with its arrow on the control's centre rather than parked where the control was mid-animation; that follow runs for any shown tip, so a control already inside the box but still moving is tracked too. The rect is compared at half-pixel resolution, so subpixel jitter does not read as movement. Each frame reads visibility BEFORE the deadline, so a frame delayed past the budget (a backgrounded tab pauses `requestAnimationFrame`) still shows the tip for a control that did land. The suppression itself is unchanged for an anchor the reviewer genuinely cannot see (a soft keyboard covering it, a pinch-panned page): an episode requires the control to still be focused or hovered, is bounded as a WHOLE (one landing deadline plus an outer tracking deadline, so an animation that never settles cannot renew it), and ends when focus or the pointer moves on (taking any bubble already shown with it), on the usual dismissals (focus out, scroll, viewport change, Escape, mousedown), and when another anchor takes over - so it expires quietly rather than parking a bubble over unrelated chrome or popping one up over a control the reviewer has already tabbed past. | `tests/32-ui-batch5.spec.js` - `a control focused while the panel is still sliding in gets its tooltip once it lands (CMH-UI-14)`, `a control that never becomes visible gets no parked tooltip (CMH-UI-14)`, `focus moving on before the control lands cancels the pending tooltip (CMH-UI-14)`; source: `assets/js/95-startup.js` - `_cmTipTrack()`, `_cmTipLandTick()`, `_cmTipRectKey()`, `_cmTipOnScreen()` |
