## Packaging and first-run extraction

The plugin ships a compact `skills/commentable-html/` (only `SKILL.md`, `LICENSE`, `THIRD_PARTY_NOTICES.md`, and a single `skill-resources.zip`) so the CLI installer writes very few files. This matters on Windows, where Defender briefly locks each file as it is written and the installer aborts the whole install on the first transient lock (the `Access is denied. (os error 5)` failure) - a large file count almost never gets through. The bulky runtime (`tools/`, `references/`, `dist/`, `vendor/`) is assembled by `build.py` into `skill-resources.zip`, and a SessionStart hook unpacks it on first run per version, retrying the same transient lock the installer does not. The large tutorial (`docs/`) and worked examples (`examples/`) are NOT shipped; they live at the plugin top level and online. The editable + built skill STAGE tree lives at `dev/skill/`.

| CMH-SIZE-01 | A document carries the vendored rich-libraries payload (`cmhVendoredRichLibs`, the gzip+base64 mermaid + Chart.js bundle the OFFLINE export inlines) only when its CONTENT can actually use it, and never in the document head. It used to be stamped unconditionally into the head: measured on the shipped examples it is 1,363 KB - 55 to 61 percent of a 2.3 MB file - and it landed on line 7, so a prose-and-code review document paid for a renderer it could never call AND any tool reading the head of the file hit a megabyte-long line immediately. `finalize` now runs a last phase that drops the payload from a document whose content uses no mermaid and no chart, restores it when the content GAINS one (the decision is re-evaluated on every finalize, not made once at creation, so a stripped document that later grows a diagram is not left with a broken offline export), and moves an existing head-placed payload to just before `</body>`. Detection is done with a real HTML parser in ONE pass, not a regex, and that is not a style choice: review found three false NEGATIVES and one case of DATA LOSS in the regex version, all on documents that strict-validated cleanly. `<canvas class=cmh-chart>` was missed (CSS does not require quotes); `<canvas title="A > B" class="cmh-chart">` was missed (a `[^>]*` scan stops at the `>` inside the quoted attribute and never reaches the class); a literal `</main>` inside an HTML COMMENT truncated the scan region and hid everything after it; and worst, a document DOCUMENTING this feature that shows the payload element as a commented-out example had that authored content DELETED, because the regex matched inside the comment. The parser is quote-aware, comment-aware, and treats `<script>` as raw text - the same reading the browser gives, which is what the runtime selectors are evaluated against - and one pass answers classification, payload location, and placement in about 20 ms on a 2.5 MB document. The scan region is `#commentRoot`, matching the runtime exactly rather than the narrower CONTENT-marker span, so rich content inside the root but outside the markers cannot be missed. A second review round found three more defects in the parser version, each now a red-first test: an authored (not commented) `<script id="cmhVendoredRichLibs">` used as an EXAMPLE inside the content was deleted on the second pass, so payload identification is now restricted to scripts OUTSIDE the content root; misnested markup a browser REPAIRS (`<p><figure class="chart"></p>...<canvas>`) classified UNUSED and got stripped, so a chart figure and a canvas CO-OCCURRING in the root now count regardless of nesting, and an unclosed root is recovered at end of input the way a browser closes it rather than reported unclassifiable; and restoring the payload located the end of body by substring search, which could pick a `</body>` inside an HTML comment and bury the 1.3 MB payload there invisibly - the body end is now recorded by the parser. Every payload copy is removed in one pass, so a stale second bundle cannot survive. Two further invariants make it safe. Detection is scoped to the CONTENT region, because the built review layer's own JavaScript carries `pre.mermaid, div.mermaid, figure.chart canvas, canvas.cmh-chart` as a literal selector string - a whole-document scan matches EVERY document and silently turns the feature into a no-op. And a document whose CONTENT region cannot be located is classified `UNKNOWN` and left ENTIRELY alone: fail-safe means "do not strip", never "insert", so a minimal or foreign document is never grown by 1.3 MB.
