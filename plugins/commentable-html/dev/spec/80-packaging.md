## Packaging and first-run extraction

The plugin ships a compact `skills/commentable-html/` (only `SKILL.md`, `LICENSE`, `THIRD_PARTY_NOTICES.md`, and a single `skill-resources.zip`) so the CLI installer writes very few files. This matters on Windows, where Defender briefly locks each file as it is written and the installer aborts the whole install on the first transient lock (the `Access is denied. (os error 5)` failure) - a large file count almost never gets through. The bulky runtime (`tools/`, `references/`, `dist/`, `vendor/`) is assembled by `build.py` into `skill-resources.zip`, and a SessionStart hook unpacks it on first run per version, retrying the same transient lock the installer does not. The large tutorial (`docs/`) and worked examples (`examples/`) are NOT shipped; they live at the plugin top level and online. The editable + built skill STAGE tree lives at `dev/skill/`.

Two further invariants make it safe. Detection is scoped to the CONTENT region, because the built review layer's own JavaScript carries `pre.mermaid, div.mermaid, figure.chart canvas, canvas.cmh-chart` as a literal selector string - a whole-document scan matches EVERY document and silently turns the feature into a no-op. Four properties keep the trim safe. (1) An UNCLASSIFIABLE document is returned untouched by the FIRST branch, before any key-set logic: it has neither usage flag set, so a needed-set computed for it would be EMPTY and would strip a payload whose runtime still wants it (the runtime falls back to `<body>` when there is no content root) - fail-safe means leave it alone in the TRIM direction as well as the insert direction. (2) A library counts as carried only when its BYTES and its MIT NOTICE are both present and non-blank, and a payload carrying one without the other is a MISMATCH that gets reconciled whenever a source pair is reachable, so orphan bytes are dropped rather than silently shipped.
