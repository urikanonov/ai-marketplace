| CMH-HL-03 | The runtime tokenizer (`diffLangKnown` / `_HL_FAMILY` in `assets/js/26-highlight.js`) knows every language the author-time highlighter supports - every `highlight_code.LANGUAGE_CONFIGS` key AND every `highlight_code.ALIASES` key - so a supported language authored raw is always highlightable at runtime (via CMH-HL-01 and the diff highlighter) and can never silently render monochrome. Keeping the two sets identical is what makes the nested-fence language a shared decision. Knowing the language is not enough on its own: every family that `_hlTokenRe()` gives its own comment/string patterns to is 1:1 with an author-time language, so it also carries its own KEYWORD set in `_HL_FAM_KW` mirroring that language's `LANGUAGE_CONFIGS[lang]["keywords"]` EXACTLY - and a family may only group languages that agree, so `xml` is its OWN family rather than riding along with html: it has a much smaller tag vocabulary and, unlike html, matches case-SENSITIVELY, so the merged family used to color `<div>` and `<ROOT>` in an XML block that the baked output leaves plain.
