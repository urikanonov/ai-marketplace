| Feature id | Behavior | Covering tests |
| --- | --- | --- |
| CMH-REATTACH-10 | Handling a subset of comments prunes only handled IDs. | CMH-REATTACH-11 | Comments created on the still-displayed old revision while an agent edits the file carry that displayed revision's anchors and relocate on refresh, including across successive revisions. | `tests/101-reattachment-flow.spec.js` - `comments added on the displayed old revision while an agent edits survive two refreshes (CMH-REATTACH-11)` |
| CMH-REATTACH-12 | Unresolved text anchors are labelled Detached, retain their original quote/context and complete thread, remain searchable and copyable, and automatically recover when identifiable content returns. | CMH-REATTACH-14 | Escape and Cancel dismiss reattachment without data loss. | CMH-REATTACH-18 | The showcase slide and runtime Help explain selective handling, comments created while an agent edits, Detached recovery, manual reattachment and older-runtime limits. | `tests/101-reattachment-flow.spec.js` - `the showcase and Help explain both local revision scenarios and demonstrate Detached recovery (CMH-REATTACH-18)` |
| CMH-REATTACH-19 | Markdown and print explicitly label Detached comments so historical quote/context cannot be mistaken for a confidently located current anchor. | `tests/101-reattachment-flow.spec.js` - `Markdown and print disclose Detached anchors rather than claiming historical text is a live location (CMH-REATTACH-19)` |

| CMH-REATTACH-21 | Reattachment controls support keyboard activation and cancellation with focus restoration, and the prompt fits a narrow viewport. | `tests/101-reattachment-flow.spec.js` - `manual reattachment remains keyboard-operable and visible on a narrow viewport (CMH-REATTACH-21)` |
| CMH-REATTACH-22 | Automatic or manual anchor relocation leaves discussion request versions, messages and unanswered state unchanged.
