## Authoring input sizing

Every surface a reviewer types a comment into (the floating composer, the side-pane inline
reply/edit editor, and the in-document comment dialog's editor) sizes itself to what is being
written, and is rendered at a readable size, so a long note never has to be composed inside a
two-line box.

| Feature id | Behavior | Covering tests |
| --- | --- | --- |
| CMH-GROW-01 | Every comment-authoring textarea AUTOGROWS to fit its content - the side-pane inline reply/edit editor, the floating comment composer, and the in-document dialog's editor. It grows as the reviewer types (no scrolling inside the box and no manual drag needed) and shrinks back whenever the content needs fewer lines, including a replacement that is LONGER in characters but wraps to fewer lines; the CSS `min-height` is the floor. Measuring a shrink never scrolls the comments panel under the reviewer, an editor opened or restored on EXISTING text (editing a saved note, or a draft carried across a re-render) comes back at content size rather than collapsed, and a measurement taken while the editor is not rendered yields no height, so it is retried rather than latched. | `tests/93-autogrow.spec.js` - `the side-pane reply input grows to fit what is typed and shrinks back (CMH-GROW-01)`, `a replacement that is longer but wraps to fewer lines still shrinks the box (CMH-GROW-01)`, `a restored draft comes back at content size, not collapsed (CMH-GROW-01)`, `shrinking a draft does not scroll the comments list under the reviewer (CMH-GROW-01)`, `an existing reply opens its editor already sized to the reply (CMH-GROW-01)`, `the floating composer textarea autogrows the same way (CMH-GROW-01)`, `the in-document popover editor autogrows too, and opens sized to the note (CMH-GROW-01)` |
| CMH-GROW-02 | Growth stops at each input's declared cap (`--cmh-grow-max`, a custom property this layer enforces rather than a CSS `max-height`, which would also bound the native resize handle; a missing or nonsensical value falls back to a default and no cap may exceed the viewport), after which the box SCROLLS instead of pushing Cancel/Save out of the card or dialog. A floating surface that grew after it was positioned (the composer, the in-document dialog) pulls itself back into the viewport on both axes, and stays viewport-sized even on a short screen, so its Save button is always reachable; a viewport change re-measures and re-clamps every open editor without waiting for a keystroke. A manual drag of the `resize: vertical` handle wins: an inline height the runtime did not write switches that editor to the reviewer's size, autogrow stops adjusting it, and that hand-picked size survives a sidebar re-render along with the draft - even when the drag was not followed by any typing. | `tests/93-autogrow.spec.js` - `growth stops at a cap and the box scrolls instead (CMH-GROW-02)`, `a grown composer stays fully on screen so Save is still reachable (CMH-GROW-02)`, `a grown in-document dialog stays fully on screen too (CMH-GROW-02)`, `a short viewport never leaves a grown composer taller than the screen (CMH-GROW-02)`, `a manual resize wins - autogrow stops for that editor (CMH-GROW-02)`, `a hand-sized reply editor keeps its height across a sidebar re-render (CMH-GROW-02)`, `a drag with no typing after it still survives a re-render (CMH-GROW-02)` |
| CMH-GROW-03 | The side-pane reply/edit input is rendered at the regular chrome font (`--cp-chrome-font`), the same size as the comment note it answers and as the floating composer - not the small metadata token used for timestamps and meta rows. | `tests/93-autogrow.spec.js` - `the reply input renders at the same font size as the composer (CMH-GROW-03)` |
